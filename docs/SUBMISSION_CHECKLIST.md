# AquaAlert Submission Checklist

## Personalization

- [x] Add your name to `README.md`.
- [ ] Add your registration number to `README.md` and the report.
- [ ] Replace every bracketed placeholder in `docs/PROJECT_REPORT.md`.
- [ ] Rewrite or expand explanations using your own understanding.
- [ ] Be able to explain every function, calculation, and diagram.
- [ ] Add only evaluation results and screenshots you personally obtained.

## Repository

- [ ] Create a separate GitHub repository for the contents of this folder.
- [ ] Name it clearly, for example `aquaalert`.
- [ ] Confirm `README.md` is at the repository root.
- [ ] Set repository visibility to **Public** in GitHub settings.
- [ ] Open the repository in a logged-out/private browser window.
- [ ] Submit only `https://github.com/USERNAME/aquaalert`.
- [ ] Ensure the submitted URL contains no `/tree/` or `/blob/` segment.

## Executability

- [ ] Clone the repository into a new folder.
- [ ] Create and activate a clean virtual environment.
- [ ] Run `python3 -m pip install -r requirements.txt`.
- [ ] Run `python3 aquaalert.py` from the repository root.
- [ ] Add at least two readings and generate a summary.
- [ ] Run `python3 -m unittest -v` and confirm every test passes.
- [ ] Verify that no absolute local paths are required.

## Design artefacts

- [ ] Problem statement
- [ ] Objectives
- [ ] Functional requirements
- [ ] Non-functional requirements
- [ ] System architecture diagram
- [ ] Process/workflow diagram
- [ ] Use case diagram
- [ ] Component diagram
- [ ] Evaluation methodology

## Report and final review

- [ ] Match headings and formatting to the official course report template.
- [ ] Add screenshots from the final submitted version.
- [ ] Cite sources actually consulted.
- [ ] Run a spelling and grammar check.
- [ ] Confirm the report and repository describe the same features.
- [ ] Remove test data or personal information that should not be public.
